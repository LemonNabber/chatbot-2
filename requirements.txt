FriendBot UI requirements
Nov 23, 2026 · @Beck
Concept
Type and colour draw the line between the two sides of FriendBot: the obscured side that feels like one friendly being, and the visible side that shows it is made of other people's data. Every rule below serves that line.
• Obscured (FRIEND.BEGIN, FRIEND.START): the setup assistant and the chat as a single bot. Friendly, rounded, calm.
• Visible (FRIEND.VISIBLE): the same chat with the sources shown: names, faces, and the conversations each reply came from.
• Archive (FRIEND.VISIBLE_ARCHIVE): another person's past conversation, opened from a source. Greyscale, with the panel colours flipped.
The look is retro calm technology: an old desktop OS, a sky wallpaper, soft glows, plain outlines, slow typing. The calm surface is meant to sit uneasily with what the tool reveals.
The mockups are the reference. Where this doc says otherwise, it is a deliberate correction, listed in "Corrections to the mockups".

Loading:
• All three are self-hosted as .woff2 files in /fonts, loaded with @font-face and font-display: block. Text never flashes in a fallback font, so the font logic is never briefly wrong.
• Balsamiq Sans is free (Google Fonts, OFL), in Regular and Bold.
• Cosette Texte is also free on Google Fonts, where it is spelled Cossette Texte (two s's). OT Bulb Monoline is commercial: it needs a web licence and the font files from you (see Open questions).
• Fallbacks if a file fails: Cosette Texte → "Arial Narrow", sans-serif; Balsamiq Sans → "Comic Neue", sans-serif; OT Bulb Monoline → ui-monospace, monospace.
• Kaomoji and symbols (Д, ω, ▽, ☆, ♪, ゞ) are outside these fonts' character sets. They fall back to "Noto Sans JP", "Noto Sans Symbols 2", sans-serif at the same size.

The perception rule. A message is always set in the font the person in that conversation saw it in. Their own messages are OT Bulb Monoline; the bot's replies to them are Balsamiq Sans. This holds in the live chat, the visible view and the archive. Example: Lemon's “ok” is OT Bulb Monoline in Lemon's archive (Lemon typed it), but Balsamiq Sans in Rebecca's chat (Rebecca received it from the bot).
Draft and sent. Text in the input box is Cosette Texte, because it is still part of the interface. When sent, it reappears as a row in OT Bulb Monoline: the moment it becomes data.
Context lines. In a source block, the line that prompted the reused reply was never seen by the person whose chat this is. It is shown as raw data: OT Bulb Monoline, muted grey, with its label in muted Cosette Texte. The reused reply itself keeps the font it had in this chat.
Window titles are data. The title bar names the system's current location like a file path, so it uses the data font. Clickable window controls (the eye toggle, dock icons) are icons, not text.
Type scale and sizing
All text uses six sizes, set in rem. The root size follows the screen, so the whole window scales as one object, like the mockups.
Root size: html { font-size: clamp(14px, min(1.25vw, 2vh), 24px); }. On a 1544 × 1000 screen (the mockups' size) that is about 19px. Spacing, window sizes and radii are also in rem. The one exception is border widths (1px and 2px), which stay in px so they land exactly on the pixel filter's grid.

Other rules:
• Weight: Balsamiq Sans Bold for headlines only. Everything else is Regular. No synthetic bold or italics.
• Case: Cosette Texte labels, buttons, step titles, placeholders and user cards are uppercase (text-transform: uppercase). Typed drafts keep the user's own case. OT Bulb Monoline and Balsamiq Sans text is shown exactly as written.
• Line height: 1.05 for headlines, 1.35 for body text and messages, 1.2 for single-line UI text.
• Letter spacing: 0.02em for Cosette Texte, −0.01em for headlines, none for the other two.
• Alignment: headlines and setup body text are centred. In message rows the label is left-aligned and the message right-aligned.
• Screen size: the layout is for landscape screens 1024px wide or more. Phone layouts are out of scope for now.

Screens and components
One desktop, one window at a time. The window's title tells you where you are; its contents change by step and mode.
Desktop and window
• Wallpaper: full-screen sky photo with fine horizontal scanlines (1px dark lines every 3px, about 15% opacity), on every screen. Pixel-filtered as an image.
• Window: --chrome frame, 2px black outline, 0.75rem corner radius. Black title bar 2.25rem tall: path on the left, eye toggle on the right (chat windows only).
• Inner panel: white, 2px --line border, 0.5rem radius, 1rem inset from the frame.
• Window size: setup 57 × 38rem, centred. Chat 74 × 47rem, centred.
• Dock: centred under the window, 3rem light-grey icons with a 1px outline. Obscured: monitor (the bot's face). Visible and archive: folder, monitor, floppy disk.
• Photos: every portrait is greyscale and dithered with 4 grey levels (the stipple look of the mockups), rounded 0.5rem with a 2px border.
Setup (FRIEND.BEGIN)
A step rail on the right shows the four steps as icons: microphone, camera, person, ABC. The current step is black, the others --muted. Primary buttons sit bottom centre.
1.  Welcome. Headline “Welcome”, centred body text, INITIATE.
2.  Voice: SAY “HELLO”. A --tint graph panel: the live waveform as a thin line, the detected pitch as thick black segments, a playhead with a triangle marker, time ticks below. A square record/stop button; a small level meter bottom left.
3.  Selfie: SNAP A SELFIE. A line drawing of a camera. The live camera feed shows inside the big lens circle; the black bar with a triangle on top is the shutter. The small rectangle top left is the viewfinder.
4.  Mood: HOW DO YOU FEEL? A scrolling grid of kaomoji in cells divided by 1px lines; the selected cell fills grey. CONTINUE.
5.  Name. A centred YOUR NAME input with a 2px border. CONTINUE.
6.  Status. A black terminal box over the window: the face icon, then lines typed out in OT Bulb Monoline (Voice, Photo, Mood, Name: Success; PROFILE CREATED; Uploading to cloud… Do not close window) and a progress bar. It runs while the photo uploads and the conversation is saved.
Chat (FRIEND.START, obscured)
• Empty: headline “What's on your mind?” centred; at the bottom, a START THE CONVERSATION input on a 1px underline.
• Header: two square portrait slots with the user card centred between them, over the glow.
• Messages: a framed list of full-width rows, 2.5rem tall, 0.25rem radius, 0.5rem apart. Label left, message right. A thin custom scrollbar with a ridged grip on the right.
• Input: under the list, borderless, with a blinking caret. Messages type out with the voice sounds, as they do now.
Visible (FRIEND.VISIBLE)
• Sidebar (--sidebar, about 16rem wide): a row of person icons for this chat's contributors (the selected one white) with their count on the right; the selected contributor's user card; a two-column stack of card-shaped slots holding contributor photos, the selected one raised.
• Rows show names instead of YOU and BOT.
• Source block: a reused bot row opens into an indented, 1px-bordered block: the source person's user card on the left, ENTER ARCHIVE ↗ on the right, the context line (muted), then the reused row.
Archive (FRIEND.VISIBLE_ARCHIVE)
The same layout as visible, showing the source person's conversation, with the archive flip from “Modes and colour”. The title path grows with each level: REBECCA > LEMON > …

Open questions
The first three block the build; the rest have a stated default that will be used unless you say otherwise.
[ ] Font files: send the .woff2 (or .otf) files for OT Bulb Monoline, and confirm its web licence covers this use. (Cosette Texte comes from Google Fonts.)
[ ] Portrait slots: default reading: the right slot is you and the left slot is the bot's  face (black is the bot on the obscured side), and then in visible mode shows the most recent (or selected) user that was recycled for the bot's message. 
[ ] Step titles: you described Balsamiq Sans as covering “subheaders”. The mockups set step titles (SAY “HELLO”, SNAP A SELFIE) in Cosette Texte. Default: Cosette Texte, with “subheader” meaning the setup body text.
[ ] Sidebar count: default: the icons are this chat's contributors and the number counts them.
[ ] Dock icons: default: folder opens the archive list, floppy disk saves a transcript. Or are they decorative?
[ ] Leaving the archive: default: each name in the title path is clickable and goes back to that level.
Build notes (no answer needed): the mood is stored in a new conversations.mood column (supabase/mood.sql). The user card still needs one more column, a short conversation number, added during the build. The setup order changes to voice → selfie → mood → name. The pixel filter stays off in Safari.
